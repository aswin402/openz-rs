## 2. `execute_with_schema_retries` — the ~42-line ×2 schema retry loop

New generic function in `schema_retry.rs` (its natural home, next to `evaluate_schema_retry`):

```rust
pub(crate) async fn execute_with_schema_retries<F, Fut>(
    mut run_res: anyhow::Result<crate::agent::agent_loop::RunResult>,
    json_schema: &serde_json::Value,
    label: &str,            // "delegate_task" / profile name, for the ▲ log line
    rerun: F,               // rebuilds and re-executes the child run with a corrected prompt
) -> anyhow::Result<RunResult>
where F: FnMut(String) -> Fut, Fut: Future<Output = anyhow::Result<RunResult>>
```

Body = today's loop verbatim: `evaluate_schema_retry(content, schema, attempts, 2)`; `Accepted(clean)` → set `res.content = clean_json`, break; `Retry { prompt, reason }` → `▲ [Reflection]` log + `run_res = rerun(prompt).await`; `Err` → propagate. Call sites pass a closure capturing the 11 `execute_subagent_run` params (identical at both sites: agent, session_id, name, model, workspace_dir, depth, token, timeout, default_timeout, spinner_msg).
The closure (not a params-struct) form keeps it unit-testable with a fake rerun — new tests pin: fenced-JSON accept replaces content, invalid JSON retries then accepts, error at attempt limit propagates, max 2 retries.
