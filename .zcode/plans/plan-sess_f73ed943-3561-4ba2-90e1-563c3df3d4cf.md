# Fix Ratatui Session-Handling Bugs + Scroll/UI Improvements

All changes are confined to `src/channels/ratatui/{app.rs, mod.rs, ui.rs}`. No changes to `session.rs`, `cli/agent.rs`, or the AgentLoop.

## Bug 1 — `/history` restore doesn't switch the session (correctness)

**Root cause:** `mod.rs:540` sets display-only `app.session_key`, but prompt dispatch (`mod.rs:844-861`) and `apply_session_model_selection` (`mod.rs:770`) still use the outer `session_key` local. Result: prompts append to the *old* session, and `SyncSession` then overwrites the restored view with the old session's disk content.

**Fix:** make the active session key shared and mutable:
- In `handle_ratatui_tui`, replace `let session_key = get_cli_session_key()` with `let session_key = Arc::new(tokio::sync::RwLock::new(get_cli_session_key()))`. (Tokio lock because the event loop holds it across `.await`s.)
- At every use site, snapshot `let key = session_key.read().await.clone();` right before use (prompt dispatch spawn, `SyncSession` load, `/streaming` load at `mod.rs:802`, `/new-session`, model selection at `mod.rs:770`).
- `/history` Enter handler: write the target key into the shared lock, set `app.session_key`, reload messages, and best-effort update the TUI marker via existing `write_tui_marker_in_dir(&marker_dir, std::process::id(), &key, &app.model, &app.provider)`.
- `RatatuiApp::new(...)` keeps taking an owned `String` (initialized from the lock); the field remains for display.

## Bug 2 — `SyncSession` wipes UI-only messages

**Fix:** add an `ephemeral: bool` field to `ChatMessage` (default `false` in `simple`/`from_session_message`/`tool_start`/`tool_finished`), plus a constructor `ChatMessage::notice(content) -> Self` (assistant role, `ephemeral: true`).

Add a merge method on `RatatuiApp` (pure, testable):
```rust
pub fn apply_sync_session(&mut self, disk_msgs: Vec<ChatMessage>) {
    let mut kept: Vec<ChatMessage> = self.messages.iter().filter(|m| m.ephemeral).cloned()
        .rev().take(5).collect(); // keep last 5 ephemeral notes, newest-first
    kept.reverse();
    self.messages = disk_msgs;
    self.messages.append(&mut kept);
    self.scroll_to_bottom();
}
```
The `TurnEvent::SyncSession` handler calls `app.apply_sync_session(msgs)` instead of `app.messages = msgs`.

Convert these UI-only messages to `notice()`: "Turn cancelled/interrupted by user" (Ctrl+C, Esc), `TurnEvent::Error` output, "✓ Switched this session to …", "⚠ Failed to switch model", "✓ Restored session …", "Started a fresh conversation session."

## Bug 3 — startup "resume history" duplicates sessions

**Root cause:** `mod.rs:212-217` copies the selected session's messages into the CLI session key; the original `cli:history_*` file remains → duplicate `/history` entries.

**Fix:** adopt-in-place, no copy. Startup selection when `selected != 0`:
- archive the current session only if it's non-history-keyed and non-empty (reuse `archive_current_session`),
- set the shared key to `selected_item.key`,
- let the existing `session_manager.load(&session_key)` at `mod.rs:234/263` populate the view.

Add one small helper in `mod.rs` used by startup, `/history` restore, and `/new-session`:
```rust
async fn reset_active_session(shared: &RwLock<String>, sm: &SessionManager, base_key: &str) {
    let cur = shared.read().await.clone();
    if !cur.starts_with("cli:history_") {
        let _ = crate::cli::archive_current_session(sm, &cur).await;
    }
    *shared.write().await = base_key.to_string();
}
```
This also prevents `/new-session` from re-archiving an already-archived `cli:history_*` session (which would create a duplicate history copy — same class of bug).

## Improvement 4 — guard in-flight turns (Enter / restore / new-session)

If `app.is_thinking` is true:
- Enter with a non-slash prompt → do not dispatch; push `notice("⏳ A turn is still running — Ctrl+C to cancel.")` and keep the typed input.
- `/history` Enter restore and `/new-session` → push a similar notice and ignore.

This removes invisible mutex-queueing of prompts.

## Improvement 5 — scroll constants + `u32` offsets

- Top of `mod.rs`: `const TICK_MS: u64 = 50; const SCROLL_STEP: u16 = 3; const SCROLL_JUMP: u16 = 2; const SCROLL_STEP_EM: u16 = 4; const SCROLL_PAGE: u16 = 8; const SCROLL_HALF: u16 = 10;` — replace the inline `3/8/2/4/10` literals and the `Duration::from_millis(50)` in `event::poll`.
- `app.rs`: change `scroll_offset`/`max_scroll` and scroll-method params from `u16` to `u32` (prevents saturation past 65,535 timeline lines). `ui.rs` computes `let max_scroll = (total_lines as u32).saturating_sub(viewport_height as u32);` and casts to `usize` when skipping lines.

## Tests (new `#[cfg(test)] mod tests` in `app.rs`)

- Scroll machine: `scroll_up` from auto-scroll disables auto and lands at `max_scroll - n`; clamps at 0; `scroll_down` re-engages auto-scroll at the bottom edge; no-op when already auto; `scroll_to_top/bottom`.
- `apply_sync_session`: replaces disk messages, preserves ephemeral notices, caps kept notices at 5, resets scroll to bottom.
- `from_session_message`: extracts `tool_name`/`tool_details`/`reasoning`/`thinking_time` from `extra`, defaults `ephemeral == false`.
